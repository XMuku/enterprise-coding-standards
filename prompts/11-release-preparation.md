# 11 GitHub 发布前整理

这是本规范包的发布准备提示词，默认不产生远端操作。具体清单和当前无许可证决定见 [发布说明](../docs/releasing.md)。

```text
请检查并完善 enterprise-coding-standards 的 GitHub 发布准备，不创建远端、不推送。
仓库路径：<KIT_ROOT>
本次要完善的文档/版本说明：<TASK>
拟发布版本：<实际版本；没有指定就先核对，不自创正式 Release>
维护者已决定本仓库不添加 LICENSE，不选 MIT/Apache-2.0/Unlicense/CC0。

1. 读取仓库 AGENTS.md、README、CONTRIBUTING、CHANGELOG、docs/releasing.md 和当前差异。
   确认无许可证是当前明确选择，不再写待决定，也不能写“无许可限制/可任意商用”。
   保留 package.json 的 private: true 和 license: UNLICENSED；UNLICENSED 不是 The Unlicense。
   不改变第三方代码和依赖自己的许可/声明，不把上游许可证当成本仓库许可证。

2. 检查 README 到 Skill、规则、提示词、示例和评测的导航是否可用。
   命令与目录必须真实；版本一致，安装、采用、检查、运行和发布的含义分清。
   不写不存在的远端 URL、徽章、下载量、企业认证或未运行的评测成绩。

3. 审查拟提交文件及需要发布的历史范围，检查凭证、个人路径、隐私和第三方内容。
   .gitignore 只能防部分新增文件被追踪，不能清除已有索引或历史秘密。
   发现疑似秘密仅报告位置和处理建议，不输出原值，不自动重写历史。
   排除 .tmp、依赖目录、构建产物、备份和聊天记录；不能只凭目录名认定安全。

4. 运行 npm run check，记录有效结果。
   改到示例/反例/评分器时运行对应检查；未改动而沿用历史结果要标注日期和版本。
   依赖审计、安全告警、独立评测中断、缺少平台/运行环境均保留，不为发版隐藏。
   没有在 GitHub 执行 CI 就写未运行；本地通过不等于远端矩阵通过。

5. 在允许范围修正文档、导航、版本和验证记录；不改变用户尚未批准的规则语义。
   区分可以公开草稿、可标测试版、是否适合生产的不同结论。
   许可证选择不影响第三方授权核查，也不豁免安全和隐私要求。

6. 最终给出发布准备结果、实际验证、已知风险和仍需维护者决定的事项。
   不创建仓库、不提交、不推送、不打标签、不创建 Release、不改可见性。
   若随后用户明确要求真正上传，再核对账号、仓库名称、可见性、目标分支和内容范围。
```
