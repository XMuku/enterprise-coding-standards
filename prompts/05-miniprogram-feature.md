```text

规范仓库：<KIT_ROOT>

先读取 SKILL.md、项目适用规则、画像、references/common.md 和 miniprogram.md。
核对 project.config.json、app.json、真实 miniprogramRoot、语言与构建方式、分包和组件注册。
若为框架生成工程，说明实际类型并沿源工程修改，不在生成目录做原生改动。
寻找同类页面和服务层，检查用户已有差异；不复制其他项目 AppID、密钥或私有配置。

核对画像中的页面、组件、API、传输与可选业务服务/平台适配职责映射，先定位真实文件。
同名配套按实际需求创建，不要求每页四个非空文件；组件声明、注册和必要逻辑不可遗漏。
不允许 API 持有 Page 实例或反向调用 setData；简单调用不另建空转发服务。

写入前决定：
- 页面/组件相对路径、文件组合、路由/分包/usingComponents 注册和命名。
- Page/Component 的职责、properties、事件、状态归属与生命周期。
- 请求参数/响应、错误和登录态机制；业务身份必须由服务端可信机制确认。
- loading/空/错误/成功/重试/重复点击等状态及资源清理。
- 列表更新、分页、异步竞态、平台能力和隐私授权相关验收。

实施要求：
1. 沿用项目的 JS/TS 与 WXML/WXSS/JSON 组织，不引入 Vue 路由或浏览器 DOM 假设。
2. 视图状态通过正确的数据更新路径同步；避免无界大对象刷新与高频冗余 setData。
3. 不把只供内部使用的数据全部传到视图；列表 key 稳定，事件数据经过校验。
4. 请求/定时器/监听在页面隐藏、卸载或组件销毁时按需要取消或失效。
5. 使用平台能力前按项目实际基础库核对，不擅自提高最低版本或开启新敏感能力。
6. 错误、拒绝授权、登录过期有实际处理，不隐藏失败，也不将生产秘密带入前端。
7. 更新路由、分包、资源和组件引用时校对大小写，不手动修改生成产物。

验证要求：
对纯逻辑运行项目现有测试；按实际脚本运行类型/静态/构建检查。
有开发者工具时验证路由、分包、生命周期、请求失败与恢复及受影响交互。
涉及平台特有能力时记录真机与基础库验证范围；环境不可用就标记未验证。
仅构建成功不表示已上传、不表示真机通过；云开发仅在项目已有且本次授权时使用。

最终报告变更、真实路径、实际验证、未验证的平台能力和必要后续事项。
不自动安装工具、改 AppID/生产域名、引入云服务、上传代码、提审或发布。
```
