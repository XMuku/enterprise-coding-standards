首次相关写入前说明：
1. 业务模块、真实包名前缀、计划新建/修改的相对路径和依赖方向。
2. Controller/应用服务/领域/持久化各自职责，沿用已有架构而非新造平行层。
3. DTO、方法、字段名称及类型、单位、范围、可空性；不以 Entity 直接充当公开响应。
4. 是否需要接口/基类及真实原因；没有替换边界就不建一对一空接口，不造万能 BaseService。
5. 方法/路径、请求/响应、分页/排序、错误码/状态码和旧调用方兼容策略。
6. 身份来源与对象级权限、租户边界（仅项目确有租户时）、幂等/重复提交、事务边界。
7. 正常、边界、拒绝、失败和兼容测试；不适用项简述理由。

实现要求：
- 使用现有依赖注入、校验、异常映射、日志与鉴权设施，不在 Controller 堆业务或 SQL。
- 从可信认证上下文取得身份；客户端字段不能代替授权判断。
- 输入校验与领域不变量分别处理，外部字段允许集明确，避免批量绑定敏感字段。
- 金额/时间/标识符遵从项目语义；Java 属性、JSON 字段与数据库列分别确认映射。
- 事务要核对实际代理调用和异常语义，不能看到注解就宣称可回滚。
- 查询限制结果集、稳定排序与分页，避免循环查库；SQL 参数绑定，动态标识符使用允许集。
- 数据迁移使用现有机制，先隔离验证，不直接修改生产数据或重写已应用的迁移。
- 外部调用明确超时/失败处理，重试考虑幂等，不泄露堆栈或凭证。

验证要求：
先确认基线与测试发现规则；关键缺陷/边界可复现时先建立失败测试。
按改动补业务测试、HTTP/序列化契约测试、权限拒绝测试、实际事务/持久化测试。

确认测试数量和架构扫描非空；不要关闭规则、跳过模块或降低断言。
对公开 API 的消费者与旧接口做受影响回归，不把整个项目没跑的测试标成通过。

最终交付行为变化、关键路径、契约/迁移影响、实际命令与结果、尚未验证项。
