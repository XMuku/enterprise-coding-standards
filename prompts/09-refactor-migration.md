# 09 有边界的重构与迁移

与 [变更管理](../references/change-management.md)、[仓库结构](../references/repository-structure.md) 配套；数据库迁移还需 [数据访问](../references/data-access.md)。

```text
请按 enterprise-coding-standards 执行下述明确范围的重构或迁移。
规范仓库：<KIT_ROOT>
项目：<PROJECT_ROOT>
目标、原因与验收：<TASK>
允许变化的模块/契约/依赖：<明确范围>
必须保持的行为与兼容期：<填写；关键未知项先确认>
是否涉及数据迁移：<默认不操作生产数据>

先读取项目规则、SKILL.md、references/common.md、change-management.md 及相关技术栈规范。
确认工作区差异、真实消费者、调用图、公开符号、路由、反射/配置引用和生成边界。
区分“不改变外部行为的重构”与“改变契约/数据的迁移”，不能混为一个笼统清理任务。

写入前给出：
- 旧对象到新对象的映射，实际目录/包/文件/符号名称及职责。
- 为什么现有边界不够用，哪些接口/继承被保留、移除或替换，以及对调用者的影响。
- 字段类型/单位/空值、JSON/数据库映射、错误与 API 行为是否变化。
- 受影响消费者、兼容过渡、验证和恢复策略；未找到的消费者不能当作不存在。
- 分步骤的最小迁移顺序，每步保持可验证，不创建长期并存的两套平行架构。

执行：
先建立相关基线与行为/契约回归，再实施最小步骤。
更新真实 import、路由、资源、配置、文档和测试；注意大小写敏感环境与反射字符串。
不运行无差别全仓字符串替换，不重写用户已有修改，不借机升级无关依赖。
公开契约变更按已确认策略处理，不能修改测试期望来掩盖意外行为变化。

涉及数据库/持久化格式时：
使用项目迁移机制，说明锁/约束/索引、已有数据、读写兼容和失败恢复的影响。
在隔离环境演练，必要时分扩展、迁移、收缩阶段；不假定所有迁移可逆。
不得重写已经应用的迁移、直接删生产数据或用“回滚”名义执行破坏性命令。
真实生产执行必须另有明确目标与授权，不属于本模板默认范围。

验证：
每步核验受影响行为，最终运行相关静态/架构/类型/构建/契约/集成检查。
确认旧行为保留或变化符合已批准验收，消费者迁移与未验证环境分开报告。
迁移失败保留证据，先确认已发生的副作用，不盲目重放非幂等操作。

交付映射与兼容变化、真实验证、仍需迁移的消费者和明确风险。
不自动提交、推送、打标签、发布、部署或清理无法确认归属的文件。
```
