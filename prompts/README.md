# 可直接使用的 Agent 提示词

**日常只选一份，不要把本目录全部发送给 Agent。** 这些提示词是任务请求模板，不是新的系统权限；必须遵守目标 Agent 的运行环境、适用项目规则与用户实际授权。

## 最短上手路径

1. 已有项目但没有规则入口：先用 [00 项目采用](00-adopt-project.md)，仅整理文档和检查计划。
2. 开发具体需求：选择下面最贴近任务的一份，替换路径与需求，把其中的 `text` 代码块作为请求。
3. 规则已采用以后：只发下方“日常短提示词”；大需求再用完整模板，不重复安装 Skill。

提示词中的 `<KIT_ROOT>` 是本规范仓库的实际绝对路径，`<PROJECT_ROOT>` 是业务项目实际绝对路径，`<TASK>` 是你的具体任务。尖括号不是要执行的 shell 变量，必须替换；不要填写密钥或生产凭证。其余可选项没有信息时写“从项目核对”，涉及关键业务决定时由 Agent 提问，不能假设已经批准。

Agent 能访问本地文件时，可以直接说“读取 `<KIT_ROOT>/prompts/02-java-spring-api.md`，用于项目 X，需求 Y”。文件内的占位符由你在请求中提供的真实值绑定，而不是让 Agent 猜测路径。

纯聊天环境不能凭磁盘路径读取文件：附上选定的提示词、适用项目规则、[开发前约束](../references/common.md)、相关技术栈规则和必要代码即可。缺少工具时只能给出方案/代码草稿，不能声称已经修改或测试本地项目。

## 日常短提示词

适用于已经确认项目画像、且 Agent 能发现项目规则的项目：

```text
在 <PROJECT_ROOT> 完成：<TASK>。
先读取适用项目规则和已确认画像，只补读受影响的规范。
新建或改动目录、包、类型、接口、基类、字段、API 前，先确认归属、命名、依赖和契约。
保留已有修改与架构；采用最小变更，补相关测试，运行真实检查。
交付实际结果及未验证项；不安装新工具、不升级框架、不部署或发布。
```

若本次确实要新增依赖、改 CI 或部署，需要在请求中明确追加范围；不要把限制删掉后让 Agent 自由猜测授权。

## 需求怎样写才足够

比“帮我做一个规范的查询”更有效的是下面这种描述。接口名、字段、路径应采用你的项目真实约定，下面仅示范需求表达方式：

```text
在已有订单列表中增加名称搜索。
输入变化后更新结果，空白输入恢复全部；没有匹配时显示空态。
保留现有排序和分页语义，不改后端接口，不新增依赖。
慢请求不能覆盖较新的搜索结果；离开页面后清理请求/定时器。
目标平台：本项目已有的 H5 和微信小程序。
验证：匹配、无匹配、清空、网络失败、快速连续输入及旧列表回归。
```

业务尚未定义时写出未知项，Agent 可以先收敛问题。不要要求“必须一次性实现全部企业级功能”，这会掩盖范围与验收缺失。

## 文件之间的职责

| 材料 | 阅读时机 | 是否自动导出到业务项目 |
| --- | --- | --- |
| [SKILL](../SKILL.md) | 首次使用或显式指定本包 | 否；安装 Skill 与采用项目规则不同 |
| [完整流程](../docs/agent-workflow.md) | 理解阶段、复杂任务或维护流程 | 否 |
| 本目录提示词 | 用户选择任务模板时 | 否 |
| 已选 references 与项目画像 | 采用后、按任务读取 | 草稿导出包含选定规则，不代表批准采用 |
| [任务记录](../assets/task-record-template.md)、[交接记录](../assets/handoff-template.md) | 长任务或跨会话需要持久化时 | 否；按实际需要填写，不强制生成 |

导出工具仍只生成既有的 `AGENTS.md.candidate` 与 `docs/coding-standards/` 草稿。提示词库不会悄悄加入所有项目，也不会增加每次任务的必读上下文。
