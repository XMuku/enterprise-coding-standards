# 08 接入静态、架构与 CI 检查

与 [检查接入](../references/checks.md)、[规则与检查映射](../docs/rules-and-checks.md) 配套。必须先指定接入范围，不能默认把所有工具装进项目。

```text
请为目标项目接入明确指定的编码门禁，使用 enterprise-coding-standards。
规范仓库：<KIT_ROOT>
项目：<PROJECT_ROOT>
要自动检查的规则与路径：<TASK>
允许的依赖/构建配置修改：<明确范围；未明确先给计划>
是否允许修改 CI：<是/否；默认否>
历史违规处理原则：<填写或先提方案，不自动修全仓>

先读适用项目规则、SKILL.md“复核/采用”相关部分、references/checks.md 与 checks-plan。
确认实际语言、框架、解析器、插件、构建/包管理器、CI 和现有格式来源。
列规则 -> 工具/配置 -> 扫描路径 -> 本地命令 -> CI 阶段 -> 未覆盖边界。
现有工具足够时复用，不重复接入互相冲突的格式化或类型检查。

接入前明确：
1. Java 的命名/静态、架构边界和行为测试不是同一工具负责；不把 Checkstyle 当权限检查器。
2. 架构测试必须扫描真实且非空的包；排除生成目录有依据，不能排除业务源码。
3. Vue/TS/小程序分别核对解析器与真实文件匹配，未覆盖模板或平台逻辑的部分说明。
4. 版本从实际兼容性与官方资料核对，不使用 latest 或把示例锁定版本套到任意项目。
5. 锁文件用对应包管理器更新；不切换工具链、不自动 force 修全部依赖告警。

实施：
在授权范围改最少配置与必要依赖，记录规则理由和例外范围。
先确认正例通过，再在隔离副本建立能触发目标规则的最小反例。
要求反例因对应规则及有效退出码失败；缺依赖、网络错误、语法崩溃不算规则生效。
保留原行为测试，不通过删断言、放宽阈值或全局 ignore 解决接入冲突。
历史违规数量过大时区分存量与新增，给出收敛方案，不能静默接受所有违规。

仅在允许改 CI 时：
复用现有工作流，在明确范围接入门禁，核对工具版本、缓存键、权限和分支触发条件。
不把有部署能力的秘密交给不可信 PR，不自动使用高权限事件或授予写权限。
配置文件存在不等于远端 job 已通过，job 通过不等于分支保护已设置。
仓库保护设置、远端写入与发布需要另行明确范围，不从本次接入推断。

交付：
运行本地真实检查与正反例，报告命令、覆盖路径、有效结果、未覆盖规则和历史债务。
更新项目画像和检查计划；只有已真实执行的项才标为已验证。
不自动推送触发 CI，不部署、不发布，也不称这些工具完成全部企业合规审计。
```
