实现要求：
- 产品入口负责导航/装配，feature 负责业务，公共能力不能反向依赖页面或产品。
- View 绑定状态与事件；ViewModel 适配页面动作；Service/Repository 承担业务与数据边界。
- 私有组件遵从项目 view/components 选择；跨模块组件有稳定输入/事件与通用职责再抽取。
- 跨 feature 用公开契约/既有事件或产品装配，不深层导入私有实现。
- V2 项目按真实 API 使用 ComponentV2、Local、Param、Event、ObservedV2/Trace。
  Local 只用于对应组件内部状态，不能给普通 ViewModel 类字段使用。
  输入对象图与深层观察按实际规则处理，不声称 Param 等于整个对象深度不可变。
- 普通功能不自动把 V1 改成 V2；不无条件深拷贝状态、不在每个组件新建同一业务状态源。
- 请求/监听/计时器按实际生命周期处理，覆盖乱序响应、错误恢复与重复动作。
- 修改模块登记、依赖、公开入口、资源和路由后同步真实配置；必要时用项目工具更新锁文件。
- 不编辑 oh_modules/.hvigor/build 产物，不将签名、账号、SDK 机器路径写进公开仓库。
- 结构变化同步必要画像/结构文档；保持每个增量步骤可构建，不夹带 UI 重做或框架升级。
