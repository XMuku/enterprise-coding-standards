# 项目编码约束（候选，采用前合并）

本文件是候选模板，不是已批准项目规则。合并现有规则并确认项目画像后，删除本行和标题中的“候选”说明；不要创建 override 文件绕过现有规则。

## 开发前

- 项目正式决策与现有一致架构优先；保留已有修改，不升级框架、替换 ORM 或夹带无关重构。
- 新建目录/包/文件前确认归属、同类位置、命名与引用；不生成无用空目录或平行架构。
- 新增层或功能文件先查画像的工程蓝图与角色映射，确定真实路径、后缀、允许依赖和注册/测试关联；不把 HTTP 接口层等同于必建 interface。
- 新建类型/接口/基类前确认职责和调用边界；优先组合，不强制一对一空壳接口。
- 模块/组件变化前确认公共、业务和产品职责、依赖方向、输入事件、状态和资源归属；不将业务代码塞入共享层。
- 新增 API/字段/表前确认契约、权限、兼容性、事务与幂等；不凭模板猜公开接口。
- 新模块或重要契约变化简述关键决定；局部修复不要求长规划文档。
- 先把需求转成可观察验收项，再决定位置/契约、实现与回归、验证与交付；关键未知仅阻断相关动作，不逐阶段形式化审批。

## 按需读取

- 从 `docs/coding-standards/project-profile.md` 查看已确认的技术栈、路径和命令。
- 读取 `docs/coding-standards/common.md`；只读取画像中映射到受影响目录的技术栈规范。
- 创建目录、类型、接口或字段时，按 common 中的入口补读仓库结构与命名；行为、配置、依赖变化只补读对应专题，不全量加载。
- API/数据/权限相关改动读取 `docs/coding-standards/contracts-security.md`。
- 接入或修改检查时读取 `docs/coding-standards/checks.md` 与 `checks-plan.md`。
- 选择验证范围或处理复杂/高风险变更时，按 `docs/coding-standards/quality-gates.md` 在写入前确定检查项；未运行、空覆盖与工具不可用不算通过。
- 不每次阅读全文、重扫全仓或访问全部来源；版本兼容和不确定事实另行查证。

## 验证与交付

- 只使用画像中的真实命令及适用测试；未接入或未运行的检查如实说明。
- 不通过删测试、关规则、降低阈值制造通过；区分已有失败与本次回归。
- 核对测试确实被发现、扫描非空，构建不等于运行验证；区分失败、环境阻断、未运行与不适用。
- 结果简述改动、实际检查、未验证项和兼容性影响；开发授权不包含部署/发布。
