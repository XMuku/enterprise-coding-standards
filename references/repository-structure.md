# 仓库、目录与文件归属

触发：新增/移动目录、包或文件，调整模块边界、构建入口、公共代码。只改函数内部时不必读取。这里的目录是示例，不是脚手架创建清单。

## REPO-01 先找归属，再创建路径

约束：先确认实际源码根、业务模块、同类实现及消费者；每个新文件应有用途和引用者。默认按现有业务边界归属，不同时引入第二种架构。团队可以选择分层、按业务域或六边形结构，但须在项目画像中确认。

| 场景 | 正例 | 反例 |
| --- | --- | --- |
| 已有订单模块 | 在原订单模块添加一个用例 | 另建 orders-v2、new-service 平行处理同一职责 |
| 仅订单使用的校验 | 保留在订单模块内 | 为一个调用点创建全仓 common 包 |
| 前后端同仓 | 根据真实构建入口确定各自根目录 | 看到 Spring 和 Vue 就新建 backend/frontend 并搬代码 |
| 增加测试 | 放入实际测试发现路径 | 创建 tests-new 但没有测试任务扫描 |

核验：新路径与项目画像一致，模块依赖方向正确，引用和测试可解析。只有确有独立复用与稳定契约时才提取公共模块，不能仅凭两段代码相似就建立共享层。

## REPO-02 区分源码、资源、测试与产物

默认布局必须服从构建配置；采用自定义布局的项目不为“统一”而迁移。

| 工程 | 可参考的职责位置 | 注意事项 |
| --- | --- | --- |
| Maven Java | src/main/java、src/main/resources、src/test/java、src/test/resources | 包路径从 Java 源根开始；不是从仓库根开始 |
| uni-app | 真实源码根内的页面、组件、请求及静态资源 | CLI 与其他构建形态可能不同，先找 pages.json |
| 原生小程序 | miniprogramRoot 下的页面、组件和 app.json | 不把项目配置所在目录直接当源码根 |
| HarmonyOS | 实际模块内的 ets、resources 与已配置测试源根 | 从模块清单、hvigor 和 SDK 确认，不照搬目录树 |
| 多模块仓库 | 各模块自己的构建、源码与测试边界 | 不能让一个应用通过深层相对路径读取另一个应用私有源码 |

Maven 位置依据 [官方目录说明](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html)。这不要求其他构建系统采用 Maven 布局。

生成代码只能通过约定生成器更新。是否提交生成结果按项目策略决定；工具 Wrapper、锁文件和有意维护的生成 API 客户端不能被一律当垃圾删除。可再生构建输出和个人临时文件通常不提交。

## REPO-03 公共模块不是杂物箱

约束：新增 common/shared/utils 前说清稳定职责、使用方和依赖方向。基础模块不得反向依赖具体业务 Controller、页面或应用启动层。

正例：已有多个调用方共用且语义一致的金额类型。反例：将订单、登录、上传逻辑集中到 CommonUtils，以避免确定归属。只有一个调用方时默认留在局部；跨模块提取要考虑版本和消费者，不一次性制造多层抽象。

核验：构建模块依赖、import 与架构测试；仅目录叫 shared 不能证明低耦合。

模块拆分、MVVM、公共组件和多产品装配时补读 [模块架构](modular-architecture.md)。commons/features/products 是一种职责映射方案，不是所有技术栈都要迁移的目录模板。

## REPO-04 文件名和路径可移植

约束：导入、路由、资源引用与真实文件的大小写完全一致。默认避免仅大小写不同的并存路径、Windows 保留名称、结尾空格/点和个人绝对路径。

正例：OrderCard.vue 被以相同大小写导入。反例：本机文件为 OrderCard.vue，代码引用 ordercard.vue 并只在不区分大小写的机器验证。

改名需同步 import、路由、资源、测试和构建配置；仅大小写改名时确认 Git 确实记录。面向外部的路径先评估兼容性，不能只修内部引用。平台专属资源有必要例外时记录目标平台和验证方式。

## REPO-05 仓库入口与所有权

README 负责项目目的、环境和真实运行入口；项目规则负责生成前约束；业务文档不与代码分别保存冲突版本。多模块规则标明路径作用域，子目录规则不得被用来偷偷绕过父级明确约束。

锁文件随所对应清单一起维护，不擅自更换包管理器或添加另一套锁文件。需要多人负责的模块可以记录真实维护者；不知道团队账号时不生成虚构 CODEOWNERS，也不自动修改仓库权限。
