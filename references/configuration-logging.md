# 配置、日志与运行边界

触发：新增配置、日志、外部请求、缓存、后台任务或资源生命周期逻辑。只读任务涉及的小节；不要求为了规范引入配置中心、监控平台或分布式组件。

## CONFIG-01 配置有类型、单位、来源和缺省语义

约束：重要配置说明来源、必填性、有效范围和单位；缺少关键配置应明确失败，不能静默连到生产或意外关闭权限检查。默认集中绑定同一职责配置，不在多个方法复制同名键及魔法数字。

正例：订单客户端的连接/响应超时具有明确单位、有效范围和测试。反例：timeout=30 无单位；开发配置缺失时默认使用线上数据库。

配置覆盖顺序按真实框架及版本验证。Spring Boot 支持多种外部配置来源及结构化绑定，见 [官方说明](https://docs.spring.io/spring-boot/reference/features/external-config.html)；本包不复制一份对所有版本都生效的覆盖顺序。

## CONFIG-02 区分公开配置与秘密

约束：真实密钥、服务端凭证和个人配置不进入仓库、日志或客户端包。样例文件只写无效占位值与说明；凭证由项目既有机制注入，不凭空安装秘密管理平台。

前端或小程序构建使用的环境变量可能进入发布包，变量名含 SECRET 不构成保护。公开服务地址和服务端访问令牌必须分类，不把所有配置都视作可公开。

正例：提交配置键说明，由环境提供秘密。反例：在 .env.example 放入真实令牌；将完整环境对象写入错误报告。泄漏时报告受影响范围并按团队流程处理，不复述密钥。

## LOG-01 日志能定位问题而不暴露敏感内容

默认采用项目已有结构化字段或参数化日志，记录事件、结果和必要的关联 ID。错误记录需保留合适的异常上下文，避免每层重复打印同一堆栈。

约束：不记录完整认证头、密码、令牌、支付资料或无必要的个人数据；不默认打印完整请求体和响应体。外部输入作为字段值处理，必要时限制长度并防日志注入。依据 [OWASP 日志指导](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 按场景确定过滤范围。

正例：记录 order.create、失败分类和项目允许的关联标识。反例：日志字符串拼接完整请求；预期校验错误每次打印 ERROR 堆栈，掩盖真正故障。

调试日志不豁免脱敏要求。审计日志与普通运行日志分别定义访问、保留和完整性要求；本规范不虚构某个法定保存期限。

## RUN-01 外部调用有失败预算

约束：明确超时、重试条件、上限和总等待预算；避免调用链每一层重复重试导致请求放大。非幂等操作只有具备对应保护时才重试。

取消操作在项目和平台支持的范围内向下游传递；无法终止远端执行时明确结果可能未知，不能把超时当作“对方肯定没执行”。默认复用已有客户端和失败策略，不每个页面或 Service 建一套网络层。

正例：在一个明确边界实施有界重试并处理重复请求。反例：无限 while 重试；客户端超时立即重复扣款。核验失败、超时、重复与取消路径，而不只是正常响应。

## RUN-02 资源与共享状态有生命周期

约束：请求级可变状态不放入单例共享字段；线程池、队列、缓存、监听器、计时器和连接明确所有者、容量或清理时机。平台托管资源按平台生命周期使用，不能套用另一运行环境的关闭方式。

正例：页面离开时移除本页面注册的监听；缓存键包含必要的租户/权限边界，并定义过期和失效。反例：每次刷新新增监听；缓存键只用资源 ID 导致跨租户复用；每个请求创建不关闭的线程池。

只有任务真的涉及并发、缓存或后台执行时才采用相应约束，不为普通 CRUD 自动添加缓存、消息队列或线程池。
