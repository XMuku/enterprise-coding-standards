# 风险分级与验证证据

触发：选择验证范围、接入门禁、复杂变更交付或验证受阻。普通小修复只需一句风险依据和实际结果，不要求生成 JSON 或读取全部规范。本页定义项目可采用的流程，不是已经安装的 Agent Hook、CI 或合规认证。

## GATE-01 写入前确定风险与检查范围

风险同时看行为影响、涉及边界和变更规模，不只数行数；一行越权判断比一百行文案更敏感。以下为默认起点，项目已有风险分类优先。

| 档位 | 触发示例 | 写代码前确定 | 完成前的最低证据 |
| --- | --- | --- | --- |
| low | 文案、非执行注释、无行为格式调整 | 受影响文件、确认无生成/配置语义 | 差异、相关格式/链接或人工校对 |
| standard | 功能、缺陷、页面、DTO、公开接口 | 目录与角色、契约、错误路径、受影响消费者 | 相关静态/类型、回归、契约或目标平台验证 |
| high | 权限/租户、资金、事务/并发、敏感数据、破坏性迁移、发布配置 | 不变量、失败影响、隔离环境、恢复条件、操作授权 | 拒绝/并发/回滚等对应测试，边界审查，必要的真实环境证据 |

新增模块要核对依赖与注册；SQL/事务要考虑真实数据库；权限要有拒绝用例；页面要区分构建与目标端交互。路径后缀只能帮助发现范围，不能替代语义判断。实现中发现更高风险就补充计划，不为了减少检查把高风险降为文案改动。

检查计划在首次相关写入前简要确定，可复用任务说明或已有工单。每项标明 ID、范围、命令/审查类型、适用性及不适用原因；实施后按同一组 ID 汇报，不静默删掉失败项。发生合理范围变化时同时保留调整原因与旧计划，不能事后改计划伪造写前执行。

## GATE-02 配置状态与本次结果分开

[检查接入](checks.md) 的“未接入/已配置未验证/已验证/不适用”描述工具接入情况；下表描述一次运行，不互相替代。

| 本次状态 | 含义 | 交付处理 |
| --- | --- | --- |
| pass | 命令或审查确实完成，覆盖非空且无失败 | 只对声明范围报告通过 |
| fail | 检查实际发现违规或非零退出 | 保留失败与基线信息，不给全绿结论 |
| blocked | 工具、服务、权限或额度不足以完成有效验证 | 写明阻断与恢复条件，不把工具不可用当不适用 |
| not-run | 尚未执行，含未接入所需检查 | 写明原因和缺口 |
| not-applicable | 与本次改动无关，计划中已有理由 | 不能由报告自行把必查项改为跳过 |

超时、崩溃、输出无法解析、缺少插件不算成功。无命中源码、零测试或全部跳过不算有效覆盖；工具本身可启动也不代表目标规则已加载。检查接入时用最小违规与修正样例证明规则真正起效。

## GATE-03 证据绑定实际变更

完成项至少记录相对工作目录、实际命令、工具版本、退出码、真实检查数量/范围、失败/跳过数量和可追溯报告；人工或模型审查记录范围、发现及 `self` / `independent-agent` / `human`，同一 Agent 自检不得声称独立审查。

验证对象是实际源码与检查配置的快照，不只是分支名。纯已提交干净工作区可使用完整 commit；有未提交内容时，采用项目可信流程产生的内容快照标识，包含相关源码、测试、配置、锁文件及未跟踪改动。只有 HEAD 相同不能证明工作区相同。改代码或改门禁后重新验证受影响项，保留旧证据但不得复用为新结果。

本包可选 `scripts/validate-evidence.mjs` 对照独立计划与报告，检查必填值、完整 ID 集合、状态一致性、非空覆盖、相对路径和本地证据文件 SHA-256。它不运行测试、不读取 Git 来产生快照、不证明日志真实来源、不自动判断风险、不读取源码判断计划是否完整，也不能抵御同时篡改计划、报告和日志的提交者。

只在规范包原仓库中使用该可选工具；导出文档不携带脚本或 JSON 资产。没有工具时按同样口径简述结果即可，不需要安装另一套平台。若用作正式 CI 门禁，可信执行器必须独立生成快照、计划和工具报告，并保护检查配置；不能让待验收 Agent 同时重写验收标准。签名、运行器适配与平台 Stop Hook 当前未实现。

## GATE-04 验证、预览、执行不混为一谈

构建/测试、迁移预览/部署计划、实际执行是不同动作。检查前识别脚本能否改文件、联网、访问外部数据或产生费用；“只检查”不授权写生产数据。不能因为预览通过就自动 apply、迁移、推送或发布。

有外部环境操作时，限定环境、权限、同一资源的并发控制、超时和清理范围；恢复需要的前提必须可验证。对普通本地应用不强制 Terraform、云账号、OIDC 或外部 MCP。长期凭证、生产数据和个人路径不放进公开证据；脱敏副本与其哈希一起维护，不能上传原始敏感日志来证明执行。

## GATE-05 例外不是伪装通过

沿用 [规则维护](change-management.md) 的限定范围、真实批准依据和补偿验证，并补上到期日期或可检查的复审事件。没有批准只记待确认；工具不可用是阻断，不是永久豁免。到期后重新评估，不默默续期。

例外可允许项目在披露风险后另行决定是否交付，但不能把原失败改为 pass。本包记录校验器不处理豁免授权；保留 fail/blocked，业务放行由真实流程单独决定。严重度说明具体影响与触发条件；命名偏好不能和越权、数据丢失混用同一严重度。
