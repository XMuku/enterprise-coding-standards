# 检查接入说明

本页是适配流程，不是一套已经在业务项目运行的配置。版本号、插件配置、包前缀和命令从实际项目及对应官方兼容性资料确定。

| 范围 | 工具与项目材料 | 必须完成的验证 |
| --- | --- | --- |
| Java 命名与格式 | Checkstyle + Maven/Gradle 配置 + 项目 checkstyle.xml | 加入违规样例能失败，修正后通过；不与现有格式工具冲突 |
| Java 架构 | ArchUnit 测试依赖 + 对真实包结构编写的测试 | 反向依赖和循环依赖样例触发失败；测试不空匹配 |
| 补充 Java 规约 | 兼容当前 JDK/解析器的 P3C/PMD 规则 | 覆盖重要条目；排除重复或冲突规则，说明不支持的条目 |
| Vue/JS/TS | ESLint 与兼容的 Vue/TS 支持 | 选定配置形态、命中源码，故意违规可失败 |
| 类型契约 | 项目 TS/Vue 类型检查 | 真实脚本可运行；故意类型不匹配可失败 |
| 目录与路径 | 项目定制脚本或适用插件 | 区分 Java 包、Vue 组件、路由、测试及生成代码；检查大小写冲突 |
| 平台功能 | 现有构建、测试和开发工具 | 验证实际目标，不把 H5 成功扩展为全部平台成功 |
| 跨模块架构 | 实际依赖图、公开导出及适用静态工具 | 共享层反向依赖、循环和跨模块私有导入能被识别；不空匹配 |
| HarmonyOS/ArkUI | 项目 SDK/API、hvigor、测试与设备环境 | 核对装饰器位置、状态观察、模块/路由/资源登记；编译、预览与真机分开记录 |

## 实施步骤

1. 确认授权、现有工具和兼容版本，只补缺口；使用项目 Wrapper/包管理器及锁文件。
2. 记录当前基线。配置命中范围和合理的生成代码排除，不宽泛忽略业务源码。
3. 加入项目本地脚本或构建任务，配置报告和失败退出码；名称以实际脚本为准。
4. 验证失败与成功路径，防止检查未命中源码、空包测试或“打印成功”的伪门禁。
5. 用现有 CI 接入。用户未授权 CI 时只保留候选配置，不新增自动发布、外部上传或秘密。

Checkstyle 不是架构测试，也不检查全部磁盘目录；ArchUnit 不是业务测试。格式化不等于类型或功能正确。保留项目已选的一套格式来源。

## 状态记录

每项记录为：未接入 / 已配置未验证 / 已验证 / 不适用。写明命令、工作目录、覆盖范围、实际结果和未验证项。若命令可能修改文件、接触外部服务或生产环境，先识别边界，不把“检查”当作任意执行授权。

本包不带无版本依据的 pom.xml、Gradle、ESLint 或 CI 全量配置。给出目标项目后由 Agent 适配；本包的检查计划模板用于追踪，不能直接作为执行脚本。
