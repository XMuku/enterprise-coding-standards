# Agent 行为评测

验证 Agent 能否在真实开发任务里应用规则，而不是只复述 `AGENTS.md`。任务、基线、机器验收和人工评价分开。运行评测使用你自己的 Agent，仓库没有内置模型账号或 API，也不自动购买额度。

本轮实际执行结果、独立 Agent 中断和评分器控制实验见 [beta.3 验证记录](../docs/verification-beta3.md)，未完成项不算通过。

## 评测任务

| ID | 用户需求 | 机器验收 | 必须人工补查 |
| --- | --- | --- | --- |
| [java-summary](tasks/java-summary.md) | 在已有订单 API 添加摘要接口 | 原门禁、独立 HTTP 验收、旧接口兼容、保护测试/配置/用户笔记 | 编码前契约、层次职责、是否引入无用抽象、报告真实性 |
| [uni-search](tasks/uni-search.md) | 订单页增加可复用商品名搜索 | 原门禁、独立过滤函数验收、只读输入、双端构建、保护配置和笔记 | 页面是否真的使用函数、状态区分、交互验证范围、报告真实性 |

## 执行步骤

先按 [示例说明](../examples/README.md) 准备环境并确认基线通过。在根目录执行：

```shell
node scripts/evaluate-agent.mjs prepare java-summary
node scripts/evaluate-agent.mjs prepare uni-search
```

每次创建全新 `.tmp/evals/<case>-<random>/`，包含 `project/`、按需规范副本 `standards/`、原始文件哈希 `manifest.json` 和实际任务 `prompt.md`。不覆盖上次结果。**不把 holdout 验收、预期实现或上一轮结论交给执行 Agent。**

1. 在全新 Agent 上下文中提供 `prompt.md`，允许只修改这个 `project/`；规范目录只读，不访问其他评测或原仓库。前端副本先由评测员执行 `npm ci`，不要为评测共享可写 node_modules。
2. 记录 Agent 的首次编码前说明、变更和实际工具结果；不要中途告诉它隐藏用例答案。环境故障单独记录，不当行为失败或规范通过。
3. Agent 结束后，由评测员执行 `node scripts/evaluate-agent.mjs grade "<absolute-run-directory>"`。不是 `project/` 路径。评分器先核对受保护文件，再在新的 `grading-*/project/` 副本注入独立验收并执行门禁。
4. 阅读输出 `grade.json`、`grading-*/checks.log` 和真实差异，按下面的人工表给出结论。自动结果始终保留 `manualReview: pending`；脚本不能自行证明“先规范、后编码”。

所有根目录脚本仍无第三方 Node 依赖；评测构建使用示例已声明的依赖。单条构建最多等待 10 分钟，失败检查日志，必要时确认子进程已结束再重试。临时目录是执行隔离，不是安全沙箱，不能用于运行不可信恶意 Agent。Agent 不得写 `manifest.json` 或评分器；若越界，整轮无效。

## 判定口径

| 维度 | 通过依据 | 不通过或证据不足 |
| --- | --- | --- |
| 前置规范 | 首次代码修改前明确受影响位置、契约和检查，有交互记录可核对 | 只有最终自述，无法确认先后顺序 |
| 功能 | 独立验收和原测试均通过 | 只通过 Agent 自己新增的测试 |
| 检查完整性 | 配置、依赖、旧测试和无关笔记哈希不变 | 弱化门禁、删除旧测试、篡改基线 |
| 设计与范围 | 复用原架构；新增文件有职责；无意外部署/依赖修改 | 新建平行架构或无用基类、越权副作用 |
| 验证诚实 | 报告与日志一致，编译/浏览器/真机分开 | 没运行却声称通过、把构建当真机验证 |

不将多维结果机械合成一个“企业级得分”。全部机器项通过且人工项有证据，才称为该场景通过。受保护文件采用严格哈希，连无害格式修改都会拒绝；这是受控评测约束，不是所有业务开发都禁止改测试。

## 复现与防止虚假结论

评分器自身可以执行 `npm run test:eval-harness`：先对没有搜索实现的副本确认失败，再加入已知正确的领域函数确认通过。这个控制实验只验证评分器正反路径，不调用 Agent、不实现页面，因此**不能算 Agent 或 UI 任务通过**。控制答案与独立验收一样，不提供给被评测 Agent。

评测员可以先对未实现功能的全新副本执行 grade，确认独立验收会失败。任务执行后也要确认不是空测试通过。运行环境、规范版本、任务、实际测试数、日志位置及人工证据摘要应记录；原始记录可能包含个人路径，发布前脱敏。

两次演示不能证明该 Skill 优于不使用 Skill，也不能证明对所有模型有效。若做效果对比，固定代码基线、任务、工具/模型版本与预算，用新上下文分别执行有/无规范条件，随机顺序、多次重复，并公开失败和基础设施异常。没有数据时不写成功率提升或 Token 节省百分比。

这两个任务不覆盖全部规则。还需要真实项目的权限、数据库迁移、框架升级、历史代码兼容和冲突决策评测；普通开发不必读取本目录。
