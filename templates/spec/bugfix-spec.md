# 缺陷修复规格：填写任务名称

状态：待复现/已复现/实施中/待验证/完成（据实选择）。本模板不要求把小修复升级为完整新功能计划，不授权生产操作或范围外重构。

## 缺陷与复现

- 预期行为、实际行为、影响对象/版本/环境与脱敏证据：待填写。
- 安全复现步骤、输入、发生频率与实际结果：待填写；不能复现时写限制，不虚构红灯。
- 根因证据与尚未证实的假设：分开填写；症状不等于根因。
- 基线差异/失败、既有用户改动与保护路径：待填写。
- 风险与授权：待填写；一行权限/资金修改也可能 high。

## 最小写前方案

| 项目 | 必须在首次相关写入前确定 |
| --- | --- |

读取已采用 common、对应 Java 专项及命名/安全/测试规则。源码布局来自画像和同类实现，不按模板搬迁。

## 实施顺序

1. 能安全复现时先建立有效失败回归，确认运行器确实发现并执行。
2. 修复根因，保持最小差异；因新证据调整方案时保留原因。
3. 运行原问题、相邻边界、兼容及风险相关检查；历史失败与本次回归分开。
4. 对照 AC 与原问题，核查是否只遮盖症状、吞异常、放宽校验或引入范围外行为。

不能执行自动化复现时提供具体人工步骤、未验证项和恢复条件；不是“已通过”。不删测试、降阈值或无限重试直到绿灯。
