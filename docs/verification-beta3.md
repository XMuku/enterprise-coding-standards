## 独立 Agent 的真实结果

隔离场景 `java-summary` 使用独立新上下文，仅给用户任务、项目副本和 Skill；执行 Agent 没有得到独立验收或预期实现。它读取的是当时的 beta.2 规范快照和初始示例，**不是最终 beta.3 整套材料的全面评测**；后续 HTTP 严格数值配置改动不在该快照中。

| 维度 | 观察到的证据 | 结论 |
| --- | --- | --- |
| 编码前决定 | 首次文件修改前明确 Controller、响应 DTO、复用 findOrder、精确三字段与 404 契约，并说明检查计划 | 本场景有前置约束证据 |
| 回归验证 | 先新增 4 项 HTTP 用例，运行失败后才实现；其后 `mvn -o verify` 退出 0，11 项通过 | 可观察的先失败后通过 |
| 范围与保护 | 只修改 OrderController，新增 OrderSummaryResponse 和 OrderSummaryHttpTest；原配置、旧测试和受保护材料哈希不变 | 通过 |
| 独立机器验收 | 评测员另建副本，加入 2 项独立 HTTP 测试；总计 13 项通过，0 失败/跳过，命名与分层门禁通过 | 代码产物通过 |
| 最终交付 | Agent 在最终答复前触发运行额度限制，没有完整结束记录 | 中断，不算完整场景成功 |

代码产物独立验收使用评分器机器报告和检查日志；原始运行记录不随发行分发，私有运行编号与定位已移除。前置动作顺序由当次 Agent 的工具/消息记录人工复核，不是通过“规划”关键词判断。评分器输出里的 `manualReview: pending` 保持原样，本表单独记录人工复核范围；本表不是可独立核验的公开原始证据。

`uni-search` 的独立 Agent 执行尚未完成；未以主 Agent 编写的控制答案代替独立模型结果。没有开展有/无 Skill 的对照实验，不报告成功率提升、Token 节省或跨模型泛化效果。

## 依赖风险与发布阻断项

当时 uni-app 锁文件的 `npm audit` 报告：**40 个受影响依赖项，13 high、12 moderate、15 low、0 critical**。这是 npm 汇总的依赖节点数，不等于 40 个独立漏洞。原始报告不随发行分发；未来重新审计数量可能变化。

已知范围包含 Vite、express、ws、adm-zip、PostCSS 和 intlify 相关依赖。框架的 Vite peer 固定为 5.2.8，不能单独强制升到另一版本后宣称兼容；部分审计自动建议还会切到不同 DCloud 版本线。本轮没有执行 `audit fix --force`、忽略 peer 约束或关闭安全告警。

示例只允许本地学习使用；loopback 和关闭 CORS 不是完整漏洞修复。生产采用前必须完成兼容升级/替代与重新审计，再运行双端检查和业务安全测试。Java 依赖未做完整漏洞扫描，也不能宣称安全审计通过。

GitHub 远端 CI、Linux、Node.js 22、JDK 17 实际运行尚未验证。许可证仍待维护者确定，没有创建远端仓库、推送、发布或全局安装 Skill。此版本适合作为带明确限制的仓库候选，不应宣传为“开箱即用、无漏洞的企业级生产框架”。
