# A2A 高级可选扩展

默认不启用。A2A 用于独立 Agent 应用交换能力、消息、任务和产物；本地一个编码 Agent 不必部署远端协作服务。基础命名/分层/安全/spec/测试不依赖它。本次不增加 SDK、端点、注册表、认证配置或自动委托。

研读依据见 [A2A 固定快照卡片](../research/05-a2a.md)，其说明标注发布版本 1.0.0；实际接入须核对所选版本与绑定/SDK，不能只用 README 示例推断兼容。MCP 与 A2A 的工具访问/应用协作职责不同，可以互补但不混作一个基础规则载体。

## 远端交接前记录

| 项目 | 必须有的真实决定 |
| --- | --- |
| 身份与发现 | 可信 Agent Card/端点、TLS/认证、发现来源与过期策略，不在公开描述放秘密 |
| 范围与数据 | 授权任务、允许输入/产物、脱敏/分类、禁止外发内容 |
| 版本与契约 | 所选协议/绑定、输入输出/错误、产物版本与消费者 |
| 职责 | 本地集成者、远端允许动作、独立审查身份、共享文件唯一写入者 |
| 生命周期 | 消息或任务、等待/取消/失败/重试、费用/超时与去重策略 |
| 验证 | 隔离成功与拒绝/失败用例、可追溯脱敏证据与撤销方式 |

completed 只说明远端任务终态，不说明本地 AC、测试、授权或代码审查已通过。后续修订按所选协议区分新任务与旧产物，不能覆盖记录后继续声称原验收有效。接收者核对来源、契约、快照和内容；远端说明不是扩大本地权限的指令。
