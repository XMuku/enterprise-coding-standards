# 编码 Agent 项目横向分析

研读日期：2026-10-03。基线：本包 `1.2.0-beta.7`。上游结论来自 [8 张固定快照分析卡片](research/01-spec-kit.md)，属于源码和文档研读，不是上游运行验收。工具原生入口另见 [兼容说明](02-tool-compatibility.md)。

## 能力分类

| 项目与卡片 | 核心问题 | 规则约束 | 工作流/执行 | 通信/工具协议 | 本包采用方向 |
| --- | --- | --- | --- | --- | --- |
| [spec-kit](research/01-spec-kit.md) | 需求意图到实现的可追踪交付 | 规格、原则检查 | spec/plan/tasks/implement/converge，需 CLI 或人工采用 | 不是通信协议 | 简化规格、验收追踪、意图与实现复核 |
| [best-practice](research/02-best-practice.md) | 自身项目工程实践与可重复构建 | AGENTS.md、提交与安全建议 | Nix/构建/发布实际检查 | 不是通信协议 | 项目真实命令、锁定与证据；不带入技术栈 |
| [agentos-kit](research/03-agentos-kit.md) | 任务契约与多角色交付 | 范围、输出、阻塞、审查契约 | 角色提示词、交接与检查管线，另含运行组件 | 可集成但不等于协议实现 | 少量职责、输入输出、文件所有权和依赖 |
| [StaffForge](research/04-staffforge.md) | 大型角色库与多工具适配 | 多层规则、宿主适配 | 角色/运行模式/工作流体系 | 可连接外部能力 | 薄适配层、共享规则；不引入角色和运行时 |
| [A2A](research/05-a2a.md) | 独立 Agent 应用互操作 | 不提供企业编码风格 | 远端消息/任务/产物交换 | Agent 应用之间通信 | 仅高级可选说明 |
| [MCP](research/06-mcp.md) | 宿主访问工具与资源 | 不提供企业编码风格 | 工具发现/调用、上下文交换 | Agent 应用与工具资源通信 | 仅高级可选说明 |
| [OpenGAP](research/07-opengap.md) | 可移植 Agent 定义与导出 | 清单、规则、职责、知识 | 版本化定义与宿主适配 | 定义格式，不等于 A2A | 单一权威、按需加载、交接证据 |
| [Aider](research/08-aider.md) | 终端模型编码 | read 注入只读规范 | 编辑、仓库地图、Git、lint/test | 工具本身，不是协议标准 | 原生配置与保守执行默认值 |

共同点是让工作可描述、可追踪。不能把文档中的“禁止”、schema 中的“权限”或协议中的 completed 当作真实执行隔离、业务正确性或检查通过。

## 规则载体与工具适配

| 项目 | 实际载体 | Cursor | Aider | GitHub Copilot | Claude Code |
| --- | --- | --- | --- | --- | --- |
| spec-kit | 模板、命令/技能集成 | 有集成体系，需所选版本安装 | 不假定同名文件自动加载 | 有集成体系，需具体宿主 | 有集成体系，需具体宿主 |
| best-practice | 自身 AGENTS.md 与 Nix 配置 | 没有证明专用适配 | 需显式 read | 没有证明通用自动加载 | 需原生入口转接 |
| agentos-kit | 根契约、agents/*.md、工作流和安装器 | 不推断全部原生识别 | 不推断全部原生识别 | 不推断全部原生识别 | 可用契约，但需核对加载 |
| StaffForge | 注册表、解析层和多个 adapters | .mdc 导出 | 聚合文件导出不等于自动 read | 适配器存在，不替代官方确认 | 适配器存在，需核对启用 |
| A2A/MCP | 规范、schema、SDK 生态 | 与规则加载无关 | 与规则加载无关 | 与规则加载无关 | 与规则加载无关 |
| OpenGAP | agent.yaml、SOUL/RULES/DUTIES 和适配器 | .mdc 导出 | 本次未认定原生适配 | 自定义 Agent 导出，不等于仓库指令 | CLAUDE.md 导出 |
| Aider | .aider.conf.yml、read/--read | 不适用 | 官方机制 | 不适用 | 不适用 |

这张表描述上游研读范围，不是本扩展的兼容认证。采用时以各工具当前官方入口为准，而不是相信上游适配器的注释或文件名。AGENTS.md 作为语义主入口不代表每个宿主都会自动读取。

## 工作流与约束归并

| 维度 | 可合并内容 | 保留边界 |
| --- | --- | --- |
| 需求与规格 | spec-kit 的验收场景、agentos 的任务输入输出 | 小修复可行内记录，不强制整套大文档 |
| 写前设计 | 文件职责/目录/命名/依赖、接口字段、测试位置 | 本包现有 references 决定；不重建一套 Java 风格 |
| 文件保护 | 工作范围、生成物、他人改动、禁止危险操作 | 文本约束不是文件系统权限；需真实差异检查 |
| 代码实现 | 最小变更、现有抽象、安全与版本边界 | 不强制 Controller/Service/Repository 全部新建，不默认接口加 Impl |
| 验证 | 真实项目命令、返回码、失败与阻塞证据 | 规范包检查不能验收业务应用；缺环境不是 pass |
| 意图复核 | spec-kit converge 的差距复核 | 不自动运行扩展钩子；新增需求回到范围确认 |
| 提交 | 项目提交约定、可读 PR 与风险记录 | 不强制 GitFlow，不自动提交/推送他人改动 |
| 多 Agent | 依赖、交接、独立审查和产物版本 | 单写入者或不重叠范围；自评不冒充独立评审 |
| 安全 | 最小数据、身份与对象授权、参数化查询 | 不引入日志全量留存、生产权限或不可信钩子 |

## 冲突与解决

| 冲突 | 上游差异或风险 | 本扩展处理 |
| --- | --- | --- |
| 规则优先级 | 多层覆盖、子规则合并可能推翻原始规则 | 本扩展不能覆盖既有企业标准；项目事实/例外走原有确认流程 |
| 仓库身份 | 标准包维护 vs Java 业务开发 | 根 AGENTS 保持维护语义；业务采用使用独立候选入口 |
| Git 策略 | 强制分支/PR/GitFlow vs Aider 自动提交 | 跟随项目实际流程；本扩展不授权提交或推送 |
| 技术栈 | Rust/Nix/前端、最新 Java/默认 ORM | 保留现有五类规范，不新增强制栈；优先按实际 Java 版本采用 |
| 默认目录 | 新框架结构可能复制进已有业务库 | 写前映射真实目录，不迁移已有结构，不按模板批量建空目录 |
| 工具载体 | .aider.rules、AGENTS 等并非所有工具通用自动入口 | 每个宿主提供原生入口；重复的只是少量安全边界 |
| 角色/隔离 | 角色声明、schema 验证 vs 真隔离 | 不宣称硬权限；独立审查需真实独立执行和证据 |
| 合规 | 金融监管、固定留存、全量记录 | 不推广监管结论；敏感资料只按现有数据政策处理 |
| 自动化 | hooks、状态服务、安装器和外部依赖 | 本次只新增文本/配置；不安装、不新增脚本、不开外部服务 |
| 许可证 | MIT、GPL、Apache、Unlicense、过渡许可证 | 原创提炼并链接固定源；不复制实现，不改变本包无 LICENSE 决策 |

“既有企业标准优先”是本包内容的取舍政策，不是对宿主系统指令优先级的重新定义。出现现有规范之间的实质矛盾时，不自行宣称后加载的模板获胜，按项目确认与例外流程处理。

## 互补关系与推荐组合

基础采用组合：本包 references 作为规则权威，spec-kit 思路作为轻量规格，agentos/OpenGAP 思路作为交接边界，官方原生入口作为加载机制，项目既有 lint/测试/CI 作为执行证据。

StaffForge 提供薄适配层的组织经验，但不导入其实现或大角色库。Aider 是可选择的消费者，不强制安装。best-practice 的工程命令映射值得保留，Nix 与 Rust 不适合作为本包基础依赖。A2A/MCP 只在确需远端协作或工具服务时另行评审。

所有模板按需采用，不要求把 8 个项目同时部署。详细目录与规则继承见 [扩展设计](00-extension-design.md)，逐项取舍见 [决策记录](03-decision-log.md)。
